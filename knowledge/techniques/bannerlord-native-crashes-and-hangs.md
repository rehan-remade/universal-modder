# Native crashes and hangs in Bannerlord: finding them in dumps and guarding them from managed code

> Bannerlord's release client reads bone indices, clip data, action indices, weapon components and usage-set slots without
> checking them, so bad mod data crashes or freezes it natively, often seconds after the cause. This note is the method used
> to find each one (WER and watchdog minidumps, Ghidra on a copy of the client DLL), the catalogue of crash sites and hangs
> solved with their causes, and how to guard a native fault from managed code. From a Borderlands 2 total conversion
> ([`../games/mount-and-blade-ii-bannerlord/bannerlord-borderlands-2-total-conversion.md`](../games/mount-and-blade-ii-bannerlord/bannerlord-borderlands-2-total-conversion.md)).

Evidence tags: **[V]** seen in the running game or by a byte-exact round trip, **[M]** measured, **[S]** static analysis only,
**[H]** hypothesis. "TN n" = gotcha n of [`editor-free-bannerlord-assets.md`](editor-free-bannerlord-assets.md). Offsets are search
handles for the client build above and go stale on any update.

## When to use it
- Bannerlord crashes or freezes with your mod and the log shows no managed exception ("faulting module TaleWorlds.Native.dll" or nothing).
- A crash happens seconds after a spawn, at deployment end, on the first melee contact, at a death, or only in sieges.
- You need to turn a native fault into a rule your pipeline checks, or guard it with a Harmony patch on the managed call leading to it.

## How
**Method.** Strings (assert and error text) -> referencing functions; crash RVA -> function; minidump registers -> object layout. A WER
dump has no heap: scan the stack for return addresses and decode the 256 code bytes WER keeps at the fault address by hand. Compare the
editor build (more strings and asserts) with the client for the same function. Run Ghidra headless with a Java batch script on a COPY of
the DLL and keep the analysed project on disk, so each later crash costs one script run.
**Guards.** The release client has almost no range checks: bone indices and counts, clip data pointers (`bip_mov_ik`, `quad_movement`,
`blends_with`), action index -1, face morph buffers, weapon components and usage-set slots are read unchecked, while the editor build
asserts. Validate in your pipeline instead, and at every mission start log `MBActionSet.GetActionSet(code).IsValid` and
`Agent.GetMonsterUsageIndex(usage) >= 0` for each custom monster; refuse to spawn agents that fail them.
**Interop.** Managed methods call native entry points by id from the `AutoGenerated` enum order; a managed null or exception where native
expects a pointer shows up as an access violation with module "unknown". Function names below are OUR labels (the DLL has no symbols).

| RVA | analyst's label | what it does | what faulted |
|---|---|---|---|
| +0x759c47 | `movement_set_calc_direction_speeds` | reads each movement slot clip's `bip_mov_ik` distance | clip without it |
| +0x760967 | `horse_movement_select_pace` | picks the gait from `quad_movement` | unloaded quadruped sets (canonical ids) |
| +0x636b6e | usage-set lookup | buckets of the monster usage set | usage set that never loaded |
| +0x584fec | `facegen_apply_static_morph` | applies skin deform keys | morph-less face + human deform keys |
| +0x6feb3f | `IMBAnimation.GetAnimationName` path | clip lookup for (action set, action) | action index -1 |
| +0x66d5a9 | `clip_balance_table_lookup` | weapon-balance child clip table | unregistered melee clip |
| +0x669cc5 | `anim_system_set_action` | blends with `blends_with` partner for shields | partner -1 |
| +0x730550 | `xml_load_file` | raw XML read | missing file: write at address -1 |
| +0x6a1004 | `agent_ai_score_target` | scores a target | target's weapon component null |
| +0x6fcc23 | `get_bone_type_data` | body type of a bone | bone index from another skeleton |

Agent layout (client): weapon component at agent +0xad8 (allocated only if monster flag 0x4000); skeleton model bone records 0x1b0 bytes
each (+0xf0 parent, +0x104 body part, +0x110 ik-joint index), bone count a signed byte at +0x148; the agent grid is 208 x 529 cells of 1.5 m.

## Gotchas
1. **Symptom.** Native access violation 3 to 4 s after a custom-race agent spawns, when it starts to move (+0x759c47). **Cause:** the movement-set
   cache reads each movement slot clip's `bip_mov_ik` with no null check; clips written as plain clips have none. **Fix:** decide by SLOT, not clip
   name (forward, backward, strafe, rotate, `patrol_walk`, turns); write real metres per cycle; never map an idle clip into a movement slot. [TN 7, V]
2. **Symptom.** Crash about 7 s after a non-human race spawns (+0x584fec). **Cause:** the face builder applies the skin's `<deform_keys>` to a
   placeholder face mesh with no morph targets. **Fix:** empty `<deform_keys />` on every skin of a race with a fixed head; never put a human head on it. [TN 13, V]
3. **Symptom.** About 1 in 3 battles crash at deployment end (+0x6feb3f). **Cause:** our probe called `MBActionSet.GetActionAnimationName` with action
   index -1 (`act_none`); native skips the check and indexes the clip table with a heap word. **Fix:** never call action-indexed APIs with an index below 0;
   check `ActionSet.IsValid`. [TN 23, V]
4. **Symptom.** Crash at the first melee contact or on a blocked reaction (+0x66d5a9). **Cause:** the weapon-balance table is keyed by clip index; 284 melee
   actions need their clip registered, which happens only when the clip's paired-animation string equals its own name; copy mode had cleared it.
   **Fix:** set the paired string to the clip's own name. [TN 10, V]
5. **Symptom.** Process dies at start-up in "Initializing items" with fast-fail 0xc0000409, even after rolling back. **Cause:** the self-pairing name is
   copied with `strcpy_s` into a 64-byte buffer and 420 to 1,280 clip names were 64+ characters; a clip-cache size computed with the 28-bone constant;
   8,470 stale long-named clips left in the folder. **Fix:** every clip name at most 63 characters (hash tail), size from the real bone count, move stale
   clips aside. [TN 11, V]
6. **Symptom.** Crash when an agent on a custom skeleton raises a shield (+0x669cc5). **Cause:** the defend request blends with the clip's `blends_with`
   partner for any off-hand weapon that blocks ranged (every shield), looked up unchecked; our writer had cleared that field. **Fix:** keep `blends_with`
   and `continue_with`, make the target an action of every set that plays the clip, run a partner check. [TN 12; fix not run in game, S]
7. **Symptom.** Crash at game start (+0x730550) after adding a sound-event line to `project.mbproj`. **Cause:** the NATIVE sound loader reads every module's
   `project.mbproj` itself and loads each named XML raw; an XSLT-only entry with no real XML is the usual trigger. **Fix:** every engine-side entry must
   name an existing, real XML file. [TN 26, V]
8. **Symptom.** Hard freeze (no crash report, CPU busy) on the first hit on a jaw, toe, heel, cape, claw or robot arm. **Cause:** a blow with no
   hit-reaction animation puts a hit IK on the bone; its solver walks up from the last chain bone with an `ik` joint, and with none the start is bone -1 whose
   parent reads back as -1: an endless loop on a worker while the main thread spins. **Fix:** every bone with a hit capsule needs an `ik` joint (or no
   capsule, or body part none/arm), plus a Harmony prefix on `Agent.HandleBlow` (not the one-line `HandleBlowAux`, which the JIT may inline past the patch)
   remapping the bone to the nearest safe ancestor. [TN 30; dump analysis V, guard unverified for every path]
9. **Symptom.** Freeze about 3 s after deployment with riders on a custom mount, intermittent. **Cause:** the mount's `body_rotation_reference_bone` was the
   skeleton ROOT: the banking code rotates it in its PARENT's frame, parent -1 is memory before the animation result, the quaternion explodes, and the melee hit
   search then walks the agent grid for about 2^62 cells. **Fix:** no monster bone field the editor validates with "has parent" (body rotation reference, head
   and thorax look, neck root, hand and item bones, foot IK, slope bones) may be a root; a runtime guard sets `Monster.BodyRotationReferenceBoneIndex = -1`
   at mission start when `MBActionSet.GetBoneHasParentBone` is false. [dump analysis V; guard compiled, status in the game note]
10. **Symptom.** Siege with creature riders crashes seconds after spawn (+0x6fcc23); field battles never do. **Cause:** native fall damage builds a blow on the
    mount's `fall_blow_damage_bone` and `Mission.FallDamageCallback` repeats it for the RIDER, whose 28-bone skeleton has no such bone. **Fix:** keep a mount's
    fall bone below 28 and add a Harmony prefix on `Mission.FallDamageCallback` that remaps or skips. Any blow whose bone index belongs to another skeleton
    ends here: fix the class. [V]
11. **Symptom.** Crash about 3 s after a custom boss dies (+0x616dab), or a stuck agent when a custom skeleton dies. **Cause:** `ragdoll_*` monster bones name
    bones with no ragdoll body (index -1 read unchecked); the death path dereferences bone 0's ragdoll body. **Fix:** every such bone needs a body; always a
    capsule on the root bone; joints are optional. [TN 15, V]
12. **Symptom.** NaN bone frames, NaN eye position, damage `int.MinValue` and an AI that never fires, only on AI-driven agents. **Cause:** `spine_lower_bone`
    was the skeleton root: the animation init walks from the head-look bone up to it reading a per-bone record at index -1. **Fix:** no bone from
    `head_look_direction_bone` down to `spine_lower_bone` may be the root or lack a ragdoll joint to its parent. [TN 14; 15 of 84 eye samples NaN before, 0 after, V]
13. **Symptom.** A riderless creature fighter crashes in five places (weapon slots +0x6f45a6, look direction +0x6fca17, voice, formation NRE, AI target
    scorer +0x6a1004). **Cause:** native builds a non-humanoid agent only from a horse item; a character agent on a quadruped monster runs character-only steps,
    and `Agent.set_Formation` needs `HumanAIComponent`, added only for `IsHumanoid`. **Fix:** the hidden-rider jockey pair ([races note](bannerlord-custom-races-and-creatures.md));
    Harmony guards held for four sites but the scorer reads the TARGET's weapon component and still crashed. [TN 25, V]
14. **Symptom.** "Faulting module unknown, 0xc0000005" with no native frame of ours. **Cause:** a vanilla managed `NullReferenceException` inside a native
    callback is reported as an access violation. Found twice: `Markable.OnInit` with `Mission.Current` null (a test called `Utilities.QuitGame()` inside a
    mission) and `DeploymentMissionController.SetupTeams` with `InitialPlayerAgent` null. **Fix:** end the mission and quit from the map; ensure the hero
    exists before a battle. [V]
15. **Symptom.** Hangs are reported as "undecided fights" or time caps and leave nothing to analyse. **Cause:** a hang writes no crash report. **Fix:** an
    application-tick watchdog thread: the main thread stamps each tick; on a gap it logs the managed stack (an empty stack plus busy CPU means the engine
    hangs) and after 30 s writes ONE `MiniDumpWriteDump` (flags 0x1960, no heap) from a short-lived thread with a join timeout, skipped under 3 GB free. Read
    every thread's stack with the python `minidump` package. [V]
16. **Symptom.** Reading a crash dump gives the wrong frame. **Cause:** the exception context in a WER dump is the WER handler. **Fix:** scan the stack for the
    fault address (three copies); decode the 256 code bytes by hand and map the RVA to a function in Ghidra; read the managed stack from the log. Dumps lack
    heap and thread info, so thread-walking scripts fail. [V]
