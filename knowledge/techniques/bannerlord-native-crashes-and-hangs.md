# Native crashes and hangs in Bannerlord: finding them in dumps and guarding them from managed code

> Bannerlord's release client reads bone indices, clip data, action indices, weapon components and usage-set slots without
> checking them, so bad mod data crashes or freezes it natively, often seconds after the cause. This note is the method used
> to find each one (WER and watchdog minidumps, Ghidra on a copy of the client DLL), the catalogue of crash sites and hangs
> solved with their causes, and how to guard a native fault from managed code. From a Borderlands 2 total conversion
> ([`../games/mount-and-blade-ii-bannerlord/bannerlord-borderlands-2-total-conversion.md`](../games/mount-and-blade-ii-bannerlord/bannerlord-borderlands-2-total-conversion.md)).

Evidence tags: **[V]** seen in the running game or by a byte-exact round trip, **[M]** measured, **[S]** static analysis only,
**[H]** hypothesis. "TN n" = gotcha n of [`editor-free-bannerlord-assets.md`](editor-free-bannerlord-assets.md). Offsets are search
handles for the client build above and go stale on any update.

## When to use it
- Bannerlord crashes or freezes with your mod and the log shows no managed exception ("faulting module TaleWorlds.Native.dll" or nothing).
- A crash happens seconds after a spawn, at deployment end, on the first melee contact, at a death, or only in sieges.
- You need to turn a native fault into a rule your pipeline checks, or guard it with a Harmony patch on the managed call leading to it.

## How
**Method.** Strings (assert and error text) -> referencing functions; crash RVA -> function; minidump registers -> object layout. A WER
dump has no heap: scan the stack for return addresses and decode the 256 code bytes WER keeps at the fault address by hand. Compare the
editor build (more strings and asserts) with the client for the same function. Run Ghidra headless with a Java batch script on a COPY of
the DLL and keep the analysed project on disk, so each later crash costs one script run.
**Guards.** The release client has almost no range checks: bone indices and counts, clip data pointers (`bip_mov_ik`, `quad_movement`,
`blends_with`), action index -1, face morph buffers, weapon components and usage-set slots are read unchecked, while the editor build
asserts. Validate in your pipeline instead, and at every mission start log `MBActionSet.GetActionSet(code).IsValid` and
`Agent.GetMonsterUsageIndex(usage) >= 0` for each custom monster; refuse to spawn agents that fail them.
**Interop.** Managed methods call native entry points by id from the `AutoGenerated` enum order; a managed null or exception where native
expects a pointer shows up as an access violation with module "unknown". Function names below are OUR labels (the DLL has no symbols).

Agent layout (client): weapon component at agent +0xad8 (allocated only if monster flag 0x4000); skeleton model bone records 0x1b0 bytes
each (+0xf0 parent, +0x104 body part, +0x110 ik-joint index), bone count a signed byte at +0x148; the agent grid is 208 x 529 cells of 1.5 m.

## Gotchas
1. **Access violation 3 to 4 s after a custom-race agent spawns, when it starts to move (+0x759c47).** See TN 7.
2. **Crash about 7 s after a non-human race spawns (+0x584fec).** See TN 13.
3. **About 1 in 3 battles crash at deployment end (+0x6feb3f).** See TN 23.
4. **Crash at the first melee contact or on a blocked reaction (+0x66d5a9).** See TN 10.
5. **Process dies at start-up in "Initializing items" with fast-fail 0xc0000409, even after rolling back.** See TN 11.
6. **Crash when an agent on a custom skeleton raises a shield (+0x669cc5).** See TN 12 (fix not run in game).
7. **Crash at game start (+0x730550) after adding a sound-event line to `project.mbproj`.** See TN 26.
8. **Hard freeze (no crash report, CPU busy) on the first hit on a jaw, toe, heel, cape, claw or robot arm.** See TN 30.
9. **Symptom.** Freeze about 3 s after deployment with riders on a custom mount, intermittent. **Cause:** the mount's `body_rotation_reference_bone` was the
   skeleton ROOT: the banking code rotates it in its PARENT's frame, parent -1 is memory before the animation result, the quaternion explodes, and the melee hit
   search then walks the agent grid for about 2^62 cells. **Fix:** no monster bone field the editor validates with "has parent" (body rotation reference, head
   and thorax look, neck root, hand and item bones, foot IK, slope bones) may be a root; a runtime guard sets the monster's body-rotation
   reference bone index to -1 at mission start when `MBActionSet.GetBoneHasParentBone` is false. `Monster.BodyRotationReferenceBoneIndex`
   is get-only in the public API; how the guard writes it is not documented here. [dump analysis V; guard compiled, no in-game run recorded]
10. **Symptom.** Siege with creature riders crashes seconds after spawn (+0x6fcc23); field battles never do. **Cause:** native fall damage builds a blow on the
    mount's `fall_blow_damage_bone` and `Mission.FallDamageCallback` repeats it for the RIDER, whose 28-bone skeleton has no such bone. **Fix:** keep a mount's
    fall bone below 28 and add a Harmony prefix on `Mission.FallDamageCallback` that remaps or skips. Any blow whose bone index belongs to another skeleton
    ends here: fix the class. [V]
11. **Symptom.** Crash about 3 s after a custom boss dies (+0x616dab), or a stuck agent when a custom skeleton dies. **Cause:** `ragdoll_*` monster bones name
    bones with no ragdoll body (index -1 read unchecked); the death path dereferences bone 0's ragdoll body. **Fix:** every such bone needs a body; always a
    capsule on the root bone; joints are optional. [crash at +0x616dab V; which of the two causes it confirmed is not recorded; TN 15]
12. **NaN bone frames, NaN eye position, damage `int.MinValue` and an AI that never fires, only on AI-driven agents.** See TN 14.
13. **A riderless creature fighter crashes in five places (+0x6f45a6, +0x6fca17, voice, formation, +0x6a1004).** See TN 25; the working
    fix is the hidden-rider jockey pair in the [races note](bannerlord-custom-races-and-creatures.md).
14. **"Faulting module unknown, 0xc0000005" with no native frame of ours.** See "Crash triage" under Verification in the asset note.
15. **Hangs are reported as "undecided fights" or time caps and leave nothing to analyse.** See "Hangs are not crashes" under
    Verification in the asset note.
16. **Reading a crash dump gives the wrong frame.** See "Crash triage" under Verification in the asset note.
