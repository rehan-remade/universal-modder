# South Central 1985: a Victoria 2 total conversion into an LA gang-territory game

> A data-only total conversion. The world map is replaced with South LA, generated from real neighbourhood
> boundaries: 265 land provinces, 98 states and 54 playable gang sets plus LAPD, the Sheriff and La Eme as a
> sphere-leading great power. The changes include:
> - the 48 goods re-skinned as a criminal economy (crack, pistols, stolen cars, counterfeit money);
> - populations scaled to real neighbourhood sizes (~3.7M in total);
> - 1985–1992 events;
> - procedurally drawn goods icons and event pictures.
>
> It loads, plays and survived a 19-year soak at max speed (1985 → 2004) with no crash. This was checked with
> in-game screenshots, logs and a scripted soak test.

## Setup
- **Game:** Victoria II with Heart of Darkness 3.04 (Steam), on Windows 11.
  - `victoria2.exe` is only the .NET launcher. The real game is `v2game.exe`: 32-bit, ASLR, no anti-cheat.
  - That is why `um scan` reports ".NET".
- **Mod layout:** `<game>\mod\SouthCentral\` plus `<game>\mod\SouthCentral.mod`. Mods go in the game folder,
  not Documents.
- **User data and logs:** with `user_dir = "SouthCentral"` they go to
  `Documents\Paradox Interactive\Victoria II\SouthCentral\` (`logs\`, `map\cache\`).
- **Launch:**
  `Start-Process v2game.exe -ArgumentList "-mod=mod/SouthCentral.mod" -WorkingDirectory <game>`.
- **Windowed mode:** set `fullScreen=no` in `<game>\settings.txt`. Back it up first.
- **Map source:** click_that_hood `los-angeles-county.geojson` (LA Times "Mapping L.A.", 272 neighbourhoods).
- **Build:** everything is generated by Python scripts.
  - The scripts are `mapgen` → `histgen` → `econgen` → `themegen` → `eventgen` → `texgen` → `icongen` →
    `install`.
  - Nothing is hand-edited in the mod folder, so every change is a rebuild.

## Route and why
- **Chosen route:** data/script only, with `replace_path` in the `.mod` descriptor. Paradox games expose
  nearly everything as text, BMP, CSV and DDS, and that was enough for a full conversion.
- **Native work was only for diagnosis.** No exe patching: the Python ctypes debugger and capstone were used
  only to *understand* crashes. Every fix stayed in data.
- **Considered and rejected:**
  - Adapting an existing big mod (e.g. CWE). It would drag in a whole world.
  - Extending the vanilla map. You can't shrink the world without replacing `map/` wholesale.

## How the game works (what we had to learn)

### Map files (`map/`)
- **`provinces.bmp`:** 24-bit, one colour per province.
- **`terrain.bmp` and `rivers.bmp`:** 8-bit palettised. In terrain, index 254 = water. In rivers, 255 = no
  river.
- **`definition.csv`:** `id;r;g;b;name;x`.
- **`default.map`:** contains `max_provinces` and `sea_starts`.
- **`positions.txt`:** y is flipped relative to the BMP (`H - y`).
- **Also needed:** `region.txt`, `region_sea.txt`, `continent.txt`, `climate.txt`, `adjacencies.csv`.
- **No wasteland:** V2 has no real impassable wasteland, so the map edge is ringed with sea provinces.
  - We used two kinds: "outside the area" and "ocean".
  - Each is a coarse grid, so no province gets too big.
- **Province colours:** the engine expects province ids to keep the vanilla `definition.csv` colour for that
  id (see Gotcha 4). We generate the map so that province `n` uses vanilla province `n`'s RGB.

### History loading
- **`replace_path` is not recursive.** Each vanilla subfolder needs its own line.
- **`history/*` paths must use the engine's capitalisation:** `history/Provinces/<sub>`, `history/Wars`,
  `history/Countries`. Lowercase alone did not take effect.
- **The *presence* of some files creates objects:**
  - a war file with no participants creates an empty war;
  - a province file with no data resets that province.

### Economy
- **Keep the vanilla goods keys.** Techs, inventions, pop needs, the icon strip order and some hard-coded
  references assume the 48 vanilla keys. So we re-skinned them through localisation instead of adding new
  ones. Examples:
  - `furniture` = Crack, `paper` = Counterfeit money, `radio` = Motorbikes, `luxury_furniture` = Lowriders;
  - `small_arms` = Pistols, `artillery` = Assault rifles, `timber` = Stolen cars, `silk` = Cocaine kilos.
- **New buildings work:** we added two (PCP lab, meth lab) with their own production types plus artisan
  versions. They are unlocked with `activate_building` inside an existing invention.
- **Factory inputs were rescaled** so each chain's input value ≈ output value / 1.35 at the new target prices.
  Otherwise re-pricing goods makes every factory lose money.
- **Building factories depends on the ruling party.** A country can build factories only if its ruling
  party's `economic_policy` allows it (`state_capitalism` / `planned_economy`). Gangs got an "OG" party with
  `state_capitalism`.
- **Starting tech goes in `history/countries/<TAG>.txt`** (`<tech> = 1`, `<invention> = yes`). We gave every
  gang a starter kit that unlocks the basic factory types. Don't use `default_enabled` (Gotcha 8).

### Events
- **`fire_only_once = yes` is global.** The event fires for one country in the whole world, not once per
  country.
- **The `month` trigger did not fire reliably** in our tests.
- **What worked:** a year window plus `mean_time_to_happen`, with a per-country flag set in the option.
  - Trigger: `NOT = { has_country_flag = X }`.
  - Option: `set_country_flag = X`.
- **Event pictures:** 521x203 TGA, referenced as `picture = "name"` and looked up in `gfx/pictures/events/`.

### Graphics
- **Goods icon strips** live in `gfx/interface/` and hold 49 frames: frame 0 empty, then the goods in
  `goods.txt` order.

  | File | Frame size |
  |---|---|
  | `resources_big.dds` | 35x29 |
  | `resources.dds` | 28x23 |
  | `resources_small.dds` | 20x16 |

- **Uncompressed DDS works everywhere:** A8R8G8B8 with a 128-byte header, `DDPF_RGB|ALPHAPIXELS`, masks
  `00FF0000/0000FF00/000000FF/FF000000`. We never needed DXT compression.
- **Colormaps:**
  - `map/terrain/colormap*.dds` are top-down, the same orientation as `provinces.bmp`.
  - Sizes: `colormap_water.dds` 936x360 with 10 mips; the others ~1880x720 with no mips.
  - `gfx/interface/minimap.dds` is an interface texture; we fill it with political colours.
- **Flags:** `gfx/flags/<TAG>[_<gov>].tga` at 93x64. 32-bit RLE TGA is safe.

### Pops and scale
- **Shrink the regiment defines** so pops of a few hundred can raise units: in `defines.lua` we used
  `POP_MIN_SIZE_FOR_REGIMENT 30` and `POP_SIZE_PER_REGIMENT 100`.
- **Population sizes:** we set each neighbourhood's density from real-world figures (people/km²), then split
  it by an ethnic mix. That gives a realistic ~10–100k per province instead of millions.

## Build steps
1. Rasterise the neighbourhood polygons onto a canvas (LA ~46 px/km, 5616x2160 like vanilla).
   - Assign owner seeds per neighbourhood and split it among gangs.
   - k-means each owner's area into provinces of ≤ ~32 km², capped well under 70k px.
   - Fix contiguity, then wrap the land in sea grid cells.
2. Write all map files.
   - Use vanilla colours per id.
   - Keep all vanilla continent names defined. Put every land province in `north_america` and leave the
     others empty.
   - Write `region_sea.txt` as one empty region.
3. Generate the remaining data:
   - countries, parties, cultures, religions;
   - country history (techs and starter kit);
   - province history (owner, core, `trade_goods`), pops, OOBs;
   - defines, bookmarks, economy, localisation (cp1252, `;`-separated, CRLF), events, textures, icons.
4. `install.py`:
   - Write the `.mod` with `replace_path` for every vanilla folder and subfolder, in both spellings.
   - Add a placeholder file to otherwise empty folders.
   - Shadow vanilla files with empty stubs, **except** `history/provinces`, `history/wars` and
     `history/diplomacy`.
   - Copy the mod over.
   - Delete `Documents\...\SouthCentral\map\cache`.
5. Launch with `-mod=mod/SouthCentral.mod`.

## Verification
- **Oracles:**
  - Screenshots of the nation picker, political map, production screen, tech tree, build-factory dialog and
    events, read back each time.
  - `Documents\...\SouthCentral\logs\*.log`.
  - A scripted **soak test** (PowerShell + WinDrive). It launches, clicks Single Player → a nation → Play,
    sets max speed, waits N seconds, then reports the last in-game date and whether the process is alive.
- **Crash diagnosis:**
  - A ~200-line Python ctypes debugger: Wow64 thread context, EBP chain walk, module map.
  - An int3 breakpoint probe.
  - capstone disassembly around the faulting VA, plus string references to name the subsystem.
  - With ASLR, `static VA = runtime − base + 0x400000`. WER offsets are RVAs.
- **Results:**
  - The 19-year soak ran with no crash.
  - Events fired as intended: the crack event 51× (once per gang), Operation Hammer 1×, raids 51×, 1992 riots
    49×, Watts truce 2×, Eme tax 115×.
  - The AI builds factories (labs).
- **Not verified:**
  - Multiplayer.
  - Game balance beyond "AI survives 19 years".
  - Close-zoom terrain textures, which still look vanilla.
  - Unit sprites and tech pictures (vanilla).

## Gotchas
1. **Vanilla countries and provinces still loaded under the new map.** **Cause:** `replace_path` is not
   recursive, and empty mod folders replace nothing. **Fix:** one `replace_path` per vanilla subfolder, plus a
   placeholder file in each otherwise empty folder.
2. **`replace_path = "history/provinces/usa"` had no effect.** **Cause:** the engine matches its own spelling,
   `history/Provinces/usa`. **Fix:** emit both spellings for every `history/*` path.
3. **Crash in trade-goods code right after loading.** **Cause:** empty stub files for vanilla province
   histories load *after* ours (same ids, different subfolders) and wipe owner and `trade_goods`. **Fix:**
   never stub `history/provinces`. Replacing the paths is enough.
4. **Heap corruption at startup, at random places.** Several causes together:
   - Sea provinces of ~185k px: vanilla's largest is ~69.5k. Keep provinces under ~70k px.
   - A stale map cache in `Documents\...\<user_dir>\map\cache`: the engine reuses it even after the map
     changed. Delete it on every install.
   - Province colours that differed from vanilla `definition.csv` for the same id: under the debugger, our sea
     province 266 carried Aberdeen's colour. Use vanilla colours per id.
   - Missing vanilla continent names: other files reference them. Keep `north_america`, `europe`, `asia`,
     `africa`, `south_america` and `oceania` defined, even when empty.
   - `region_sea.txt` listing our sea provinces: write it vanilla-style, as an empty region.
5. **Crash when pressing Play, inside war-name formatting.** **Cause:** a stub file in `history/wars` creates
   a war with no participants. **Fix:** no stubs for `history/wars` or `history/diplomacy`.
6. **"Build factories: No" for every gang.** **Cause:** the ruling party's `economic_policy` was
   `laissez_faire` / `interventionism`. **Fix:** use a `state_capitalism` party as the starting ruling party.
7. **Only one country in the world got the "crack arrives" event, and month-based events never fired.**
   **Cause:** `fire_only_once` is global, and the `month` trigger was unreliable. **Fix:** per-country flags
   plus a year window plus MTTH.
8. **Crash about 3 weeks in.** It was at static VA 0x857559, in AI building choice: it dereferenced a
   building with no production type. **Cause:** `default_enabled = yes` on every factory building. **Fix:**
   remove it, and give starting techs and inventions in country history instead.
9. **Goods icons showed vanilla meat and fabric.** **Cause:** the icon strips are by index, not by key.
   **Fix:** regenerate the three `resources*.dds` strips in `goods.txt` order, with frame 0 empty.
10. **The harbour appeared in the north of the map.** **Cause:** we flipped the colormap vertically, assuming
    DDS was bottom-up. **Fix:** no flip; colormaps are top-down like `provinces.bmp`.
11. **"Artillery" was renamed in a confusing way.** **Cause:** the unit and the good share the localisation
    key `artillery`. **Fix:** localise it once, with a name that fits both, or drop the unit.
12. **Windows/agent environment:**
    - The Store `python` alias virtualises writes under `AppData`, so the game never saw the generated files.
      Use the real interpreter path.
    - Files written from the Bash sandbox were not always visible to Windows processes. Do file operations
      from PowerShell or the real Python.

## Assets
- **No AI image generation in the final build.** The fal account ran out of balance, so everything is drawn
  in code with Pillow.
- **48 goods icons:** drawn at 140x116, 4× supersampled, with outline and drop shadow, then downscaled into the
  three strips.
- **5 event pictures:** flat illustrations at 521x203.
- **Other generated art:** flags (5 government variants per tag, generated from gang colours), colormaps (an
  urban palette per neighbourhood type, a mile street grid, freeways, the LA River, beaches) and the minimap.

## Cost and time
- About one long agent session (~6 h wall clock), including about 1.5 h chasing startup heap corruption.
- No paid assets.

## Open questions
- Close-zoom terrain textures (`map/terrain/*.dds` atlas) and the water normal maps are still vanilla.
- No new unit sprites or tech pictures.
- Balance is untuned: police AI aggression, gang growth, and RGO output per km².
- It is unknown whether `month` triggers can work. Their failure may be specific to how we combined them with
  MTTH.
