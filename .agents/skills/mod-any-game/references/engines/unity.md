# Unity

**Identify.** `UnityPlayer.dll` and a `<Game>_Data/` folder.
- **Mono backend:** `<Game>_Data/Managed/Assembly-CSharp.dll` exists. The game logic is plain .NET IL, which
  makes modding easy.
- **IL2CPP backend:** `GameAssembly.dll` + `<Game>_Data/il2cpp_data/Metadata/global-metadata.dat`. Logic is
  compiled to native code, so mods work through generated interop.
- **Version:** `um scan` reads it from `globalgamemanagers`. It decides which loader build works.
- **Save/config path:** `%USERPROFILE%\AppData\LocalLow\<company>\<product>\` (from `<Game>_Data/app.info`).
  `Player.log` sits there too, and it is the first log to read.

## Route 1: an existing community loader (check first)
Many Unity games already have a modding scene on Thunderstore (r2modman) or Nexus. If it has a
`<game>API`/`R2API`/`Jotunn`-style library, build on that. Examples: RimWorld (XML Defs + Harmony), Valheim
(Jotunn), Risk of Rain 2 (R2API), Lethal Company, Hollow Knight (its own Modding API, installed via
Lumafly).

## Route 2: BepInEx (or MelonLoader) + Harmony
- **BepInEx 5 (Mono):**
  1. Unzip into the game folder. It adds `winhttp.dll` (the Doorstop proxy) and `doorstop_config.ini`.
  2. Run the game once to generate `BepInEx/config`.
  3. Plugins are .NET assemblies in `BepInEx/plugins/`.
  4. The log is `BepInEx/LogOutput.log`; turn on the console in `BepInEx.cfg`.
- **BepInEx 6 (bleeding edge):** needed for IL2CPP. It generates interop assemblies on the first run (slow
  once).
- **MelonLoader:** an alternative loader. It puts `version.dll` in the game folder and uses `Mods/`.
- **Proton/Linux:** set the launch option `WINEDLLOVERRIDES="winhttp=n,b" %command%` (BepInEx) or
  `version=n,b` (MelonLoader).
- **Plugin skeleton (BepInEx 5):**
  ```csharp
  [BepInPlugin("you.mymod", "My Mod", "0.1.0")]
  public class Plugin : BaseUnityPlugin {
      void Awake() { new Harmony("you.mymod").PatchAll(); Logger.LogInfo("loaded"); }
  }
  [HarmonyPatch(typeof(PlayerController), "Update")]
  static class Patch { static void Postfix(PlayerController __instance) { /* ... */ } }
  ```
  Reference `Assembly-CSharp.dll`, `UnityEngine*.dll` (from `_Data/Managed`) and the BepInEx core DLLs. Set
  `<Private>false</Private>` so they aren't copied. Target the framework the game uses (often
  `netstandard2.0` / `net472`). The `BepInEx.PluginInfoProps` + `BepInEx.Templates` NuGet templates
  scaffold this.
- **Harmony:**
  - prefix: runs before; return false to skip the original.
  - postfix: runs after; can change `__result`.
  - transpiler: edits the IL, for surgical changes.
  - Use `AccessTools` for private members.
- **IL2CPP:** patch via Il2CppInterop types (`Il2Cpp*` namespaces generated by BepInEx 6 / MelonLoader).
  Managed-side `MonoBehaviour`s must be registered with `ClassInjector.RegisterTypeInIl2Cpp<T>()`.

## Read the game
- **Mono:** ILSpy / `ilspycmd -p -o ~/<game>-decomp Assembly-CSharp.dll`, or dnSpyEx for debugging and
  editing.
- **IL2CPP:** Cpp2IL or Il2CppDumper (with `GameAssembly.dll` + `global-metadata.dat`). These give type,
  method and field layouts plus dummy DLLs to read in ILSpy. Method bodies are native: use Ghidra/IDA with
  the generated scripts to name functions.
- **Live:** UnityExplorer (a BepInEx/MelonLoader plugin) is an in-game hierarchy, inspector and C# console.
  It is the fastest way to find the GameObject and component you need. `bepinex-mcp` exposes live patching
  and field watches to an agent.
- **Assets:** AssetRipper (whole project export), UABEA / AssetStudio (browse and replace in bundles),
  `UnityPy` (Python).

## Content and assets
- Load your own assets at runtime from an AssetBundle built with the **same Unity major version** (Unity
  Hub, empty project). Or load PNGs with `Texture2D.LoadImage` and build `Sprite.Create` yourself.
- For new items or characters, clone an existing prefab (`Object.Instantiate`) and swap its mesh, material
  and stats. That is far easier than building from scratch.
- Audio: `UnityWebRequestMultimedia.GetAudioClip` for wav/ogg.

## Pitfalls
- Loader builds are tied to Unity versions. Use the one the community recommends for this game's version.
- `DontDestroyOnLoad` objects and scene reloads: hook scene loads (`SceneManager.sceneLoaded`) to re-apply
  state.
- IL2CPP stripping: methods the game never called may not exist, and generic instantiations may be missing.
- Anti-cheat (EAC/BattlEye) in multiplayer Unity games (Rust, Tarkov, Fall Guys...): no.
